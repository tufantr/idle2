- **D2 The clan boss on screen (Landing 1).** The screen rolls crits and ±10% a hit; the server counts expected values from
  the save stored just before the fight, and strikes stop when the boss falls on screen. In 2,560 simulated fights with
  the boss's health at 0.92 to 1.08 of a whole fight, screen and server disagreed 782 times (419 fell on screen only, 363
  on the server only). A sketch brought that to 0: `clanFightFells(game)` in systems/clanfight.js,
  `clanFightDamage(game.derived, cleanStrikes(f.strikes, CLAN_FIGHT_MS), CLAN_FIGHT_MS).damage * (f.scale || 1) >= f.hp`;
  in playerAttack, after `enemy.hp -= dmg`, a clan boss at 0 that the sum doesn't fell goes back to 1 HP and the fight goes
  on; when the clock ends, a boss the sum does fell falls ('felled'). The Endless Hydra must keep ending as 'time' (the
  sketch broke that test). The server doesn't change. A flagged account's cap is the server's alone.
- **D3 The top bar (Landing 1).** The header row wraps, and the bonfire pill's countdown has proportional digits (178 to 212 px
  over a burn, about 5 px between seconds), so a nearly full row flips between one and two lines and the page moves about
  38 px. This CSS, added to a copy of the live page, stopped every jump from the timer and from the pill coming and going
  from 700 to 2,000 px, with the pill never cut off:

  ```css
  .pills { flex: 1 1 240px; min-width: 240px; flex-wrap: nowrap; overflow: hidden; container-type: inline-size; }
  .pills > * { flex: 0 0 auto; white-space: nowrap; }
  .pills > .status-pill, .pills > .event-pill { flex: 0 1 auto; min-width: 44px; overflow: hidden; text-overflow: ellipsis; }
  .bonfire-pill, .focus-pill, .event-pill { font-variant-numeric: tabular-nums; }
  @container (max-width: 430px) { .pill-long { display: none; } }
  ```

  A gold figure gaining a digit still moved the bar at 900 and 1,248-1,252 px: hold the bar's height until the window
  changes. Tested in Chromium only; the report came from Firefox, so check there, and at phone widths.
- **D4 Trial bests and last runs (Landing 1).** `state.trials.best` is saved but no screen reads it; Trial cards show tiers
  and the next target, only in the prestige dialog. No run history exists, and the prestige card doesn't show the stage
  reached. Records gets each tried Trial's best and a list of the last 20 runs (a new optional field written in
  `doPrestige`: when, stage reached, tokens, time, Trials), validated in `migrateState`.
- **D5 Berserker (Landing 2, measured first).** +20% under half health. A test fight (blows of 13% of health): under half
  63% of the time at Gourmet 0, then 48, 36, 25 and 11%, and 0 at Gourmet 5 and 6, which eat below 50 and 55%. Research 015
