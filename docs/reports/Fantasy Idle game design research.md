# Fantasy Idle Needs New Curves, Not Patches

**The shipped Fantasy Idle cannot create a single piece of equipment — `getRandomRarity()` throws a `ReferenceError` on every call, a defect present since the first commit and confirmed by executing the real `main.js` in a Node harness — so the only progression chain in the game (gear → combat stage → prestige tokens → multipliers) is severed and a naked player idles to Boss 10.** Fixing that one line would expose three formulas that make the game unwinnable on a human timescale: the skill XP curve `nextXp = floor(nextXp × 1.5)` puts mining level 30 at **46 days** of continuous play and the level-75/85/90 nodes at **10^6–10^9 years**; the rarity multiplier is applied twice, so a legendary copper set (1,824 ATK) out-stats a common runite set (498) by 3.7×; and prestige tokens grow as `maxStage^1.5` while every upgrade level doubles in cost, so a fixed-gear player plateaus within **3–6 prestiges** (iron: stage 40 → 49 → 50, then stuck forever). The comparable games researched — Melvor Idle, Old School RuneScape, Clicker Heroes, Tap Titans 2, Cookie Clicker, Antimatter Dimensions, Trimps, NGU Idle, Diablo 2/3/4, Path of Exile, Legends of Idleon, AFK Arena and Idle Heroes — converge on a small set of reusable curves that Fantasy Idle lacks: the RuneScape XP formula (**13,034,431 XP at 99**, doubling every 7 levels), gold per kill proportional to enemy HP (**HP/15**), a prestige currency that is exponential in the stage reached (or a fractional power of lifetime earnings), rarity expressed as *number of affixes* with at most a ~1.5× stat stretch, a 24-hour full-tick offline replay, state-predicate onboarding, count-based achievement multipliers, bankable (never streak-based) dailies, versioned saves with migration chains, and asynchronous 2–5-attempts-per-day clan bosses. The recommended redesign adopts those curves with concrete parameters (`tokens = floor(2^((S−10)/5))` with +10% ATK/DEF per token held, `gold = ceil(HP/15)`, rating-based damage reduction, quality-plus-affix rarity, salvage/upgrade item sinks, a 24-h offline cap), cuts the systems that are broken or exploitable (the 1.5× curve, the double rarity multiplier, the Coal Wagon gold loop, the mock authentication, the placeholder clan UI, skill points), and sequences the work into six phases — hotfix, core-math rewrite with a balance simulator, retention scaffolding, loot and dungeons, skill breadth, and finally an async social layer — each with a measurable exit condition. Under the recommended skilling parameters a player reaches level 20 in about 10 minutes, level 50 in about 2 hours and level 99 in about 150 hours; under the recommended prestige formula each reset extends the run by a constant ~13 stages instead of converging to zero.

### Two defects destroy progression outright, and twenty-six more mislead or waste

The headline bug is a comma expression: `RARITIES.reduce((sum, r => sum + r.weight), 0)` evaluates the undeclared identifier `sum` before `reduce` runs, so both item generators throw on every call; because the loop consumes the 5 bars *before* the throw, every 4-second smithing cycle burns materials, aborts the remainder of that tick (skipping combat and autosave), grants no XP and repeats ([main.js:1717](../../main.js#L1717), [main.js:1305-1316](../../main.js#L1305)) **[executed: 10 iron bars → 5 → 0, no items, no XP]**. The developer's own committed save in `api/fantasy-idle.db` has an empty inventory and `maxStage: 10` — exactly the naked wall ([api/fantasy-idle.db](../../api/fantasy-idle.db)). The second S1 defect is data loss: `loadGame` returns before merging the local save when the `fantasy_jwt` token is absent, but the 50 ms loop is already registered and `saveGame()` writes the pristine default state over the real save ten seconds later; logging out therefore erases progress ([main.js:671-676](../../main.js#L671), [main.js:1388-1392](../../main.js#L1388)) **[executed: mining 40 / 12,345 gold → level 1 / 0 gold after one tick on the login screen]**. The save key is also shared across usernames, so "accounts" on one device overwrite each other.

The S2 tier is long. `wipeSave` deletes the wrong key (`fantasyIdleSave` vs `fantasyIdleSaveLocal`), so "Hard Reset" only reloads ([main.js:744](../../main.js#L744)) **[executed]**. `parseOfflineProgress` throws for smelting/smithing/crafting actions because `SKILLS_DATA[type].nodes` is undefined, and since it runs inside `loadGame` before the panels render, the page loads half-blank with no offline credit ([main.js:764](../../main.js#L764)) **[executed]**. Rogue's "(+Speed)" is gathering speed, not attack speed ([index.html:182](../../index.html#L182), [main.js:2064](../../main.js#L2064)) **[executed]**. The header auto-eat select offers shrimp/trout/salmon/lobster/shark that exist in neither `state.resources` nor `FOOD_HP`, so choosing one silently never eats, and the id `auto-eat-select` is duplicated ([index.html:71](../../index.html#L71), [index.html:92](../../index.html#L92)) **[executed]**. "Combat Lv" permanently reads `highestPrestigeStage` after the first prestige ([main.js:877-882](../../main.js#L877)). The gold-shop Healing Potion restores HP that every spawn already refills ([main.js:867](../../main.js#L867)). The prestige modal promises to keep "All Non-Combat … Resources" and lose only "Combat Gold", but the code zeroes all gold and there is no combat gold ([index.html:419-423](../../index.html#L419), [main.js:951](../../main.js#L951)). Autosave happens only from the loop, never on `beforeunload`/`visibilitychange`, so up to 10 s of progress — including a prestige — is lost on tab close ([main.js:1388-1392](../../main.js#L1388)). Item "(Lv N)" labels are never checked on equip ([main.js:1746](../../main.js#L1746)) **[executed: a Lv 4 legendary equips at combat level 1]**; the boss `dodgeChance` is written and never read ([main.js:862](../../main.js#L862)); smithing and crafting levels are granted but never displayed or used ([main.js:1314-1322](../../main.js#L1314)); the five minigame panels rebuild their `innerHTML` every 250 ms, including the alchemy `<input type="range">` ([main.js:1394-1398](../../main.js#L1394)); `state.stats` and `combat.enemy` are persisted then recomputed ([main.js:667](../../main.js#L667)); and the repository tracks `api/node_modules` (1,099 files), `.DS_Store` files, a SQLite database containing a real username and bcrypt hash, an API with a hard-coded fallback JWT secret and non-expiring tokens, and a `/api/save` that stores any 5 MB JSON body unvalidated ([api/index.js:11](../../api/index.js#L11), [api/index.js:65-80](../../api/index.js#L65)).

### The XP curve makes 8 of 14 mining nodes unreachable in a lifetime

The 1.5× geometric curve needs **220,753 XP for level 20→21, 12.7 million for 30→31, 734 million for 40→41 and 4.2×10^10 for 50→51**; `nextXp` exceeds 2^53 at level 81 ([SIM §1a](file:///tmp/claude-0/-home-user-idle2/822a3f17-4006-5034-be72-45cc3ca07351/scratchpad/audit-sim.mjs)) **[simulated]**. Against that, the best node XP/s rises only from 3.33 (amethyst, Lv1) to 13.33 (diamond, Lv85), a ×4 gain over 85 levels versus a ×10^15 requirement, so no re-tuning of node XP can rescue the curve — the exponent itself must change ([main.js:147-208](../../main.js#L147)).

### Every idle wall lands on a boss, and the token shop cannot move it

Because enemy ATK grows 10% per stage but a boss doubles it, one boss step equals **ln 2 / ln 1.1 = 7.3 regular stages** of ATK growth, while player DEF is a flat subtraction: a common iron set (36 ATK / 59 DEF / 690 HP) is immune to stage 39 (ATK 37) and takes 23 per hit from Boss 40 (ATK 82), dying in 60 s against a 486 s kill ([SIM §2c](file:///tmp/claude-0/-home-user-idle2/822a3f17-4006-5034-be72-45cc3ca07351/scratchpad/audit-sim.mjs)) **[simulated; naked → stage 10 and iron → Boss 40 reproduced in the real loop, executed]**. Walls for common sets sit at Boss 40 (copper/iron/silver), 50 (mithril/gold), 60 (adamant) and 70 (runite); legendary sets — which are 64× commons, not 8× — reach 70–100 before a 10-minute kill-time limit. Token levels move a common-gear wall by at most one bracket: DEF-only reaches stage 49 at level 5 (31 tokens) and 50 at level 8 (255 tokens), then stays at 50 through level 20 (1,048,575 tokens), because crossing Boss 50 with iron needs DEF ≈ 205, i.e. level 24 ≈ 16.7 million tokens ([SIM §2c-iv](file:///tmp/claude-0/-home-user-idle2/822a3f17-4006-5034-be72-45cc3ca07351/scratchpad/audit-sim.mjs)).

The prestige economy is convergent at every scale: tokens are **0 below stage 11, 10 at stage 50, 31 at 100 and 88 at 200**, while each +10% level doubles in cost and buys ≤ 1 stage. A greedy loop simulation with common iron gives maxStage 40 for prestiges 1–5, 49 at prestige 6, 50 at prestige 16 and 50 thereafter with 45 tokens unspent; mithril plateaus at 60 from prestige 12; legendary iron sits at 80 on every one of 25 prestiges ([SIM §3d](file:///tmp/claude-0/-home-user-idle2/822a3f17-4006-5034-be72-45cc3ca07351/scratchpad/audit-sim.mjs)) **[simulated]**. Skill points are 1–4 per account lifetime (1 per 50 all-time stages), so Knight/Warlord/Rogue are cosmetic. The daily reward, where its legacy gate passes, pays 23 tokens per day at `highestPrestigeStage` 46 versus 9 tokens for a full prestige at the same stage — a login bonus larger than the core loop ([main.js:1688](../../main.js#L1688)).

### Gold has no job, and offline time has no limit

Gold enters only through selling at flat category prices and the (broken) daily reward; combat produces nothing **[executed]**. Because a 60-second diamond sells for the same 18 gold as a 3-second amethyst, **mining amethyst at level 1 is the best gold activity in the game (21,600 gold/h)**, and the Coal Wagon (250 gold → 100 coal → resells for 600) nets +350 per cycle, reaching the 100,000-gold "Capitalist" achievement in 286 cycles ([SIM §4a-c](file:///tmp/claude-0/-home-user-idle2/822a3f17-4006-5034-be72-45cc3ca07351/scratchpad/audit-sim.mjs)) **[simulated; wagon executed]**. Total meaningful gold demand per run is ≤ 750 gold. Woodcutting exists for one potion ingredient (`oak_wood`); normal, willow, maple, yew and magic wood have no consumer ([main.js:166-171](../../main.js#L166), [main.js:204](../../main.js#L204)); silver and gold bars (power 2, below iron's 3) are strictly worse than iron as armour ([main.js:94-95](../../main.js#L94)). Offline progress trusts the client's `Date.now()` with no cap and simulates only the active gathering node without the minigame boost: 30 days away on Copper Vein yields 1,296,000 copper, 6.48 M XP (mining 1 → 26) and 7.8 M gold if sold; a year on amethyst yields 189 M gold ([SIM §6](file:///tmp/claude-0/-home-user-idle2/822a3f17-4006-5034-be72-45cc3ca07351/scratchpad/audit-sim.mjs)) **[simulated; 36 copper per offline minute with Rogue ×4 executed]**. ## Comparable games converge on reusable curves for every system

### Skilling: one XP formula, two timing models

Old School RuneScape and Melvor Idle use the identical curve `XP(L) = floor(¼ Σ_{ℓ=1}^{L−1} floor(ℓ + 300·2^(ℓ/7)))`: **83 XP to reach level 2, 13,363 for level 30, 101,333 for 50, 1,986,068 for 80 and 13,034,431 for 99**, with the exponential term dominating from about level 30 so that the requirement doubles every 7 levels — level 92 is exactly half of 99 and level 85 one quarter ([OSRS Wiki: Experience](https://oldschool.runescape.wiki/w/Experience)) **[code-dump]**. RuneLite implements it as `difference = (int)(level + 300.0 * Math.pow(2.0, level/7.0)); xp += difference; XP_FOR_LEVEL = xp/4` ([RuneLite Experience.java](https://github.com/runelite/runelite/blob/master/runelite-api/src/main/java/net/runelite/api/Experience.java)) **[code]**, and Melvor's client carries the same `equate(level)` plus an O(1) inverse, `xpToLevel = floor(7·log2(2^(1/7) + ((2^(1/7) − 1)/75)·xp)) − 1`, then a one-step correction ([Melvor utils.js](https://github.com/ChanceToZoinks/melvor-source/blob/main/src/utils.js)) **[code]**; Melvor's cap is `hasTotHEntitlement ? 120 : 99` (120 = 104,273,167 XP) ([Melvor skill.js](https://github.com/ChanceToZoinks/melvor-source/blob/main/src/skill.js)) **[code]**. The curve paces well because every 7 levels cost as much as everything before them: the first 50 levels are 0.78% of 99, so early tiers unlock in minutes while 99 remains a 150–400-hour goal at un-boosted rates (10k XP/h → 1,303 h; 36k → 362 h; 86.4k → 151 h) **[computed]**.

The two games differ on timing. OSRS rolls for success every N ticks with `P = (1 + floor(low·(99−L)/98 + high·(L−1)/98 + 0.5))/256`, so level and tool both matter without changing the interval; woodcutting rolls every 4 ticks, pickaxes only change roll frequency (bronze 8 ticks → rune 3 → dragon 2.83), and rune ore at 99 with a rune pickaxe is 19/256 per 3 ticks ≈ 24 s per ore ([OSRS Wiki: Skilling success rate](https://oldschool.runescape.wiki/w/Skilling_success_rate), [Mining](https://oldschool.runescape.wiki/w/Mining), [Pickaxe](https://oldschool.runescape.wiki/w/Pickaxe)) **[code-dump]**. Melvor is deterministic: `modifyInterval = max(250, round(interval × (1 + pct/100) + flat))`, mining `baseInterval = 3000` ms with rock HP `5 + masteryLevel` and a respawn timer, smithing/herblore 2,000 ms, crafting 3,000 ms, cooking passive slots at 5× the active interval ([Melvor skill.js](https://github.com/ChanceToZoinks/melvor-source/blob/main/src/skill.js), [rockTicking.js](https://github.com/ChanceToZoinks/melvor-source/blob/main/src/rockTicking.js), [cooking.js](https://github.com/ChanceToZoinks/melvor-source/blob/main/src/cooking.js)) **[code]**. Per-action XP grows roughly 10–25× from first to last node while intervals only grow 2–4×: OSRS logs run 25 → 380 XP, ores 17.5 → 240 ([OSRS Wiki: Woodcutting](https://oldschool.runescape.wiki/w/Woodcutting), [Mining](https://oldschool.runescape.wiki/w/Mining)); Melvor's yew is 80 XP/6 s, magic 100 XP/10 s, redwood 180 XP/7.5 s ([Melvor Wiki: Woodcutting](https://wiki.melvoridle.com/w/Woodcutting)) **[snippet]**. Melvor's long tail is Mastery: per-node levels on the same XP table, `masteryXP = ((unlockedActions × totalMasteryLevel / maxTotalMastery) + actionMastery × (totalActions/10)) × (interval/1000) / 2`, a pool capped at `500,000 × actions` with checkpoints at 10/25/50/95%, and per-skill effects such as mining doubling `+floor(m/10)%`, cooking success `70 + 0.6·m%` (100% at 50), smithing preservation `+floor(m/20)×5%` and herblore potion tiers at mastery 1/20/50/90 ([Melvor skill.js](https://github.com/ChanceToZoinks/melvor-source/blob/main/src/skill.js), [mastery2.js](https://github.com/ChanceToZoinks/melvor-source/blob/main/src/mastery2.js), [herblore.js](https://github.com/ChanceToZoinks/melvor-source/blob/main/src/herblore.js)) **[code]**. Both games enforce one action at a time — Melvor's `idleChecker` stops whatever else is running, and combat is registered as an active action alongside the skills — with Township (300-second wall-clock ticks) and passive cooking as the only parallel exceptions ([Melvor game.js](https://github.com/ChanceToZoinks/melvor-source/blob/main/src/game.js), [township.js](https://github.com/ChanceToZoinks/melvor-source/blob/main/src/township.js)) **[code]**.

### Economy: escalating inputs, count-based sinks, value that scales with tier

OSRS keeps low-tier nodes relevant with escalating inputs: coal per bar is **0 / 0 / 2 / 4 / 6 / 8** (bronze, iron, steel, mithril, adamant, rune), so a level-30 rock is the bottleneck for level-85 gear ([OSRS Wiki: Bar](https://oldschool.runescape.wiki/w/Bar), [Coal](https://oldschool.runescape.wiki/w/Coal)) **[code-dump]**; Melvor pushes the schedule to 4/8/12 for mithril/rune/dragonite and treats coal as a first-class cost with its own reducers (`decreasedSmithingCoalCost`) ([Melvor smithing.js](https://github.com/ChanceToZoinks/melvor-source/blob/main/src/smithing.js)) **[code; ratios snippet]**. Bars per item are fixed by slot — dagger 1, scimitar 2, platelegs 3, platebody 5 — and smithing XP is simply bars × per-tier XP (12.5 → 75 per bar), while levels follow "tier base + item offset": bronze 1, iron 15, steel 30, mithril 50, adamant 70, rune 85, with dagger +0, scimitar +5, square shield +8 and platebody +18, so smithing unlocks something at nearly every level ([OSRS Wiki: Smithing](https://oldschool.runescape.wiki/w/Smithing)) **[code-dump]**. Stat growth per tier is super-linear (scimitar slash +7/+10/+15/+21/+29/+45/+67) and item *value* grows ~×3–5 per tier (dagger 10/35/125/325/800/8,000), which is what lets crafted goods out-value raw inputs: a rune platebody alchs for 39,000 coins against 9,600 for its five runite ores ([OSRS Wiki: Smithing](https://oldschool.runescape.wiki/w/Smithing)) **[code-dump]**. Silver and gold are crafting metals for jewellery, not armour ([OSRS Wiki: Silver bar](https://oldschool.runescape.wiki/w/Silver_bar), [Gold bar](https://oldschool.runescape.wiki/w/Gold_bar)); cooking needs a heat source; logs feed firemaking (40 → 350 XP per log), fletching (15 arrow shafts per normal log, +15 per tier) and construction (1 log + 100 coins per plank) ([OSRS Wiki: Cooking](https://oldschool.runescape.wiki/w/Cooking), [Firemaking](https://oldschool.runescape.wiki/w/Firemaking), [Fletching](https://oldschool.runescape.wiki/w/Fletching), [Sawmill operator](https://oldschool.runescape.wiki/w/Sawmill_operator)) **[code-dump]**. Herblore pairs a herb with a secondary sourced from another skill (crushed nests from woodcutting, volcanic ash from mining, wine from cooking), and Melvor generalises the rule: the secondary comes from the skill the potion buffs ([OSRS Wiki: Herblore](https://oldschool.runescape.wiki/w/Herblore), [Melvor Wiki: Herblore](https://wiki.melvoridle.com/w/Herblore)) **[code-dump; snippet]**.

Gold sources and sinks are equally structured. OSRS injects gold through High Level Alchemy (60% of an item's value, ~1,200 casts/hour) and drops, and removes it through tool shops (pickaxes 1 / 140 / 500 / 1,300 / 3,200 / 32,000 coins), service fees and a bank-space ladder whose nine blocks cost 1M, 2M, 5M, 10M … totalling 888M ([OSRS Wiki: High Level Alchemy](https://oldschool.runescape.wiki/w/High_Level_Alchemy), [Pickaxe](https://oldschool.runescape.wiki/w/Pickaxe), [Bank](https://oldschool.runescape.wiki/w/Bank)) **[code-dump]**. Melvor's shop uses `Linear`, `Fixed`, `Glove` and `BankSlot` cost types and prices bank slots by `floor(2654570 × 50·L / 142015^(163/(120+L)))` capped at 5,000,000 GP — 34 GP for the first slot, 3,557 for the 21st, 2.2 M for the 101st ([Melvor shop.js](https://github.com/ChanceToZoinks/melvor-source/blob/main/src/shop.js)) **[code; evaluations computed]**. Both games make the last sinks aspirational rather than required.

### Combat and prestige: gold tracks enemy HP, prestige tracks progress exponentially

Every endless-stage idle game puts enemies on an exponential and ties income to it. Clicker Heroes' current formula is `HP = ceil(1.55^(zone−1)·10 + (zone−1)·10)` to zone 140, then ×1.145 per zone to 500, then a base that creeps up by +0.001 every 500 zones to a 1.545 cap; bosses every 5 zones are ×10 HP with a 30-second timer; **gold per kill is `ceil(HP_old/15 × min(3, 1.025^(zone−75)))`**, i.e. literally a fraction of monster HP ([ClickerHeroesTracker monster.ts](https://github.com/dfederm/ClickerHeroesTracker/blob/fe535216fa41111c9b531c189e3d9afae324229b/WebClient/src/models/monster.ts), [userData.ts](https://github.com/dfederm/ClickerHeroesTracker/blob/fe535216fa41111c9b531c189e3d9afae324229b/WebClient/src/models/userData.ts)) **[code]**. Hero cost grows ×1.07 per level while DPS gets ×4 every 25 levels, so DPS-per-gold decays ~1.2% per level and a run stalls gradually rather than abruptly ([VikeStep calculator](https://github.com/VikeStep/Clicker-Heroes-Calculator/blob/326dd2e59c0df12bed6de05310d2118730aeeeba/ClickerHeroesCalculator.js)) **[code]**. The prestige currency is exponential in progress: post-transcendence hero souls per primal boss are `20·(1+TP)^(zone/5 − 20)`, each soul gives +10% DPS (`heroSouls·10` percent), and the tracker's own optimiser compares the soul-growth exponent to the HP exponent (`alpha = ln(1+TP)·1.4067 / ln(hpScale)`) — the game's balance tooling explicitly keeps the two in step ([outsiderSuggestions.ts](https://github.com/dfederm/ClickerHeroesTracker/blob/fe535216fa41111c9b531c189e3d9afae324229b/WebClient/src/components/outsiderSuggestions/outsiderSuggestions.ts), [ancientSuggestions.ts](https://github.com/dfederm/ClickerHeroesTracker/blob/fe535216fa41111c9b531c189e3d9afae324229b/WebClient/src/components/ancientSuggestions/ancientSuggestions.ts), [Clicker Heroes blog: Primal Bosses](https://blog.clickerheroes.com/primal-bosses-clicker-heroes-tips-and-farming/)) **[code; blog snippet]**. Souls are spent on ancients with linear (`n`), triangular (`n(n+1)/2`), `Σ i^1.5` or capped exponential (`2^(n+1) − 1`) costs, and a second layer, Ancient Souls = `floor(5·log10(lifetime souls))`, compresses the numbers ([ancientSuggestions.ts](https://github.com/dfederm/ClickerHeroesTracker/blob/fe535216fa41111c9b531c189e3d9afae324229b/WebClient/src/components/ancientSuggestions/ancientSuggestions.ts), [blog: Ancient Souls](https://blog.clickerheroes.com/clicker-heroes-ancient-souls-master-the-ultimate-currency/)) **[code; snippet]**. Tap Titans 2's 2017 server variables show the same architecture: `titan_hp = 17.5 × 1.39^min(stage,115) × 1.13^max(stage−115,0)`, boss multipliers `[2,3,4,5,8]` capped by `min(1.1^(stage/200), 2.5)`, gold `0.008·HP + 0.0002·min(stage,150)`, relics `((max(0, stage−75)/14)^1.75)`, hero cost ×1.082, taps capped at 20/s with crit chance ≤ 0.5 ([TT2-Sim ServerVarsModel.py](https://github.com/metxchris/TT2-Sim/blob/ef0e375a8a876b336ac893a1240f5d9baf776533/ServerVarsModel.py)) **[code]**.

Pecorella's rule explains why Fantasy Idle walls: exponential growth "will eventually catch and far exceed any polynomial growth no matter how big k is or how small n is", so idle games put costs and enemies on the exponential and production on the polynomial, then use prestige to "slide the curve up" ([Pecorella, Math of Idle Games (GitHub mirror)](https://github.com/manhonggang/Notes/blob/05a4d8834cf3b04a781c9a480dc58f0898c63ba3/%E8%A7%81%E9%97%BB%E8%B5%84%E6%96%99/The%20Math%20Behind%20Idle%20Games%20(A%20Study%20by%20Kongregate)%20-%20GameAnalytics.md), original [Game Developer Part I](https://www.gamedeveloper.com/design/the-math-of-idle-games-part-i)) **[article mirror]**. The prestige term must itself grow exponentially in progress or the wall is permanent: AdVenture Capitalist's angels `150·√(lifetime/10^15)` need ~4× more earnings to double, Cookie Clicker's `∛(lifetime/10^12)` needs 8×, Egg Inc.'s `(run/10^6)^0.14` needs 128×, and "if you reset at the same point you will earn literally no more prestige currency" under a √ formula ([Pecorella Part III (mirror)](https://github.com/manhonggang/Notes/blob/05a4d8834cf3b04a781c9a480dc58f0898c63ba3/%E8%A7%81%E9%97%BB%E8%B5%84%E6%96%99/The%20Math%20Behind%20Idle%20Games%20(A%20Study%20by%20Kongregate)%20-%20GameAnalytics.md)) **[article mirror]**. Antimatter Dimensions gives exactly 1 IP per infinity until "Break Infinity", then `10^(log10(antimatter)/308 − 0.75)` ([AD src/game.js](https://github.com/IvarK/AntimatterDimensionsSourceCode/blob/5409e320cecef96a917cca1dfb68f1f183e499ca/src/game.js)) **[code]**; Idle Slayer prices each Slayer Point at `12 + 4 × lifetime SP` and advises ascending when the gain would add 10–20% to the lifetime total ([Idle Slayer Wiki: Ascension Strategy](https://idleslayer.fandom.com/wiki/Ascension_Strategy)) **[snippet]**; NGU penalises rebirths shorter than 60 minutes down to 0.00031% at 3 minutes ([NGU Idle Wiki: NUMBER](https://nguidle.miraheze.org/wiki/NUMBER)) **[snippet]**. Applying the stall model to Fantasy Idle's numbers (HP ×1.15 per stage, gear roughly linear), a permanent multiplier M moves the wall by `ln(M)/ln(1.15)` stages — ×2 buys 5 stages, ×4.05 buys 10 — so tokens must be roughly exponential in stage with base ≈ 4 per 10 stages for each prestige to keep paying ([combat notes, KQ4 inference](../research_notes/Fantasy%20Idle%20game%20design%20research/combat_scaling_and_prestige.md)) **[inference]**.

Melvor shows the authored alternative. Player and enemy share one stat pipeline: `accuracy = evasion = (effectiveLevel + 9) × (bonus + 64)`; hit chance `1 − 0.5·evasion/accuracy` when accuracy ≥ evasion, else `0.5·accuracy/evasion`; `maxHit = floor(10 × (1.3 + L/10 + B/80 + L·B/640))` with L = level + 9 — a cross-term that makes levels and gear multiply; damage reduction capped at 95% and modulated by a combat triangle (melee vs magic damage ×0.85, reduction ×0.75); combat XP 0.133 Hitpoints XP per point of damage; auto-eat when `HP ≤ threshold%` refilling to a limit% at a per-tier efficiency; death sets HP to 20% and deletes one random equipped item ([Melvor character.js](https://github.com/ChanceToZoinks/melvor-source/blob/695f1b1b9f886b6f492958e8182a699563afd9e1/src/character.js), [player.js](https://github.com/ChanceToZoinks/melvor-source/blob/695f1b1b9f886b6f492958e8182a699563afd9e1/src/player.js), [combatTriangle.js](https://github.com/ChanceToZoinks/melvor-source/blob/695f1b1b9f886b6f492958e8182a699563afd9e1/src/combatTriangle.js)) **[code]**. Enemies carry hand-authored levels (Chicken 3 HP · 1/1/1 up to god bosses 1,000–1,200 HP · 500–600 levels), dungeons are ordered monster lists whose progress resets on leave or death and whose reward fires only on completion, and the idle-safety rule is `HP × autoEatThreshold > maxHit × (1 − DR)` ([Melvor Monsters.js (v0.18 mirror)](https://github.com/espoire/Melvor-Idle-Combat-Simulator/blob/87a8073f18cefc9a7cb0f490b20ddb6c1155180c/scripts/melvor/Monsters.js), [combatManager.js](https://github.com/ChanceToZoinks/melvor-source/blob/695f1b1b9f886b6f492958e8182a699563afd9e1/src/combatManager.js), [gridster2 DR compendium](https://github.com/gridster2/Melvor/blob/main/Documents/Compendium%20of%20Damage%20Reduction.md)) **[code]**. Active combat in the clicker games is a bounded overlay: a non-critical Clicker Heroes click does 3.5% of DPS, Juggernaut's combo counter is tuned to `primary^0.8`, and TT2 caps taps at 20/s and crit at 50% ([Steam: How good is Juggernaut?](https://steamcommunity.com/app/363970/discussions/0/594820656474926915/), [TT2-Sim ServerVarsModel.py](https://github.com/metxchris/TT2-Sim/blob/ef0e375a8a876b336ac893a1240f5d9baf776533/ServerVarsModel.py)) **[snippet; code]**.

### Loot: rarity counts affixes, tiers set power, sinks make every drop fuel

No mature ARPG gives rarity a large stat multiplier. In Path of Exile, Normal has no affixes, Magic 0–1 prefix and 0–1 suffix, Rare 1–3 of each (4/5/6-mod split 8/12, 3/12, 1/12), and Unique has fixed mods ([PoE Wiki: Rarity](https://pathofexile.fandom.com/wiki/Rarity), [poe-crafter calculator.js](https://github.com/Decnalabnu/poe-crafter/blob/main/src/utils/calculator.js)) **[snippet; code]**; affix *tiers* are gated by item level and the top tiers are also lower-weighted — Life prefixes run +3–9 (ilvl 1) to +110–119 (ilvl 81, body armour only), and local physical-damage tiers fall from weight 1,000 to 25 ([Path of Building ModItem.lua](https://github.com/Openarl/PathOfBuilding/blob/81eeead3f6c9ba62f8a02fc305b742d5ecae3ead/Data/2_6/ModItem.lua)) **[code]**. Diablo 2 caps item level at the monster's level and rolls quality with `(base − (mlvl − qlvl)/divisor) × 128` ([Diablo 2 Wiki: Item Generation](https://diablo2.diablowiki.net/Item_Generation_Tutorial)) **[snippet]**; Diablo 3's Loot 2.0 limits items to 4 primary affixes, makes ~85% of drops class-appropriate, and its Ancients stretch a stat range from 500–750 to 751–1,000 (≈1.33×) ([Diablo Wiki: Loot 2.0](https://www.diablowiki.net/Loot_2.0), [Smart Loot](https://www.diablowiki.net/Smart_Loot)) **[snippet]**; Diablo 4's Greater Affixes roll at 1.5× one affix's maximum, item power is binary at endgame (850 vs 900), and masterworking adds a deterministic +1% per rank to 25 ([D4Scanner gearing doc](https://github.com/defessler/D4Scanner/blob/6418927743523e405092c4b658f982fa0e2791d9/docs/d4-gearing-knowledge.md)) **[code-hosted doc]**. Melvor has no rarity at all — a Rune Scimitar is a fixed 2.4 s, 7/45/7 attack, 44 strength — and its craftable ladder grows ×1.4–1.6 per metal tier (scimitar strength 6→9→14→20→28→44→66; platebody defence 15→21→32→46→65→82→109) with drop-only bands (Ancient, Godswords at 245–340 strength) 1.2–2× above the top craftable, while enemy max hits rise ~25× (52 → 1,300) and the player closes the gap with stacking percentage DR (practical maximum 81–82%) ([Melvor Items.js (v0.18 mirror)](https://github.com/espoire/Melvor-Idle-Combat-Simulator/blob/87a8073f18cefc9a7cb0f490b20ddb6c1155180c/scripts/melvor/Items.js), [gridster2 dungeon DR tables](https://github.com/gridster2/Melvor/blob/main/Documents/Damage%20Reduction%20Tables%20for%20Dungeons.md)) **[code]**. NGU has no tiers within an item: level 0–100 gives +1% per level, duplicates merge deterministically (level = sum + 1), and a maxed zone set grants a set bonus ([NGU guide inventory.md](https://github.com/sayolove/ngu-guide/blob/aa50a4ffe38f6dbf6bc1390edd616bee7f6cf668/src/content/docs/en/mechanics/inventory.md)) **[code-hosted guide]**. Multiplicative stats are always tamed: PoE dodge caps at 75% and "increased" modifiers sum before "more" multiply, D4 caps crit and attack speed at 100% and converts armour through `V/(V·10/9 + C)`, WoW diminishes avoidance by `1/((1/c) + (k/a))` ([PoE Wiki: Dodge](https://pathofexile.fandom.com/wiki/Dodge), [Wowpedia: Dodge](https://wowpedia.fandom.com/wiki/Dodge), [D4Scanner](https://github.com/defessler/D4Scanner/blob/6418927743523e405092c4b658f982fa0e2791d9/docs/d4-gearing-knowledge.md)) **[snippet; doc]**.

Drop budgets in Melvor's data are single-digit percent for tier-appropriate gear and 0.05–0.3% for the best drop of a monster: Rune Knights (5% loot chance) yield each Rune piece at 0.625% per kill, a Black Platebody is 1/2,040, Dark Horned Elite's Ancient 2H Sword 1/1,126, and dungeon chests make the rarest piece 0.16–0.5% per clear (Ancient Platebody 0.28%); across 193 equipment entries the median per-kill chance is ~3% ([Melvor Monsters.js](https://github.com/espoire/Melvor-Idle-Combat-Simulator/blob/87a8073f18cefc9a7cb0f490b20ddb6c1155180c/scripts/melvor/Monsters.js), [Items.js](https://github.com/espoire/Melvor-Idle-Combat-Simulator/blob/87a8073f18cefc9a7cb0f490b20ddb6c1155180c/scripts/melvor/Items.js)) **[code; computed]**. Of 609 Melvor equipment items, 236 are craftable, 152 drop from monsters, 144 come from chests and only 87 are both — crafting sets the base ladder, combat supplies materials (dragonhide ×10, bars, runes), fragments (Dragon Claw Fragment 12% per Griffin kill) and the capstone band ([Items.js](https://github.com/espoire/Melvor-Idle-Combat-Simulator/blob/87a8073f18cefc9a7cb0f490b20ddb6c1155180c/scripts/melvor/Items.js)) **[code; computed]**. Diablo 3 backstops luck with a hidden ~2-hour legendary pity timer and scales legendary odds by difficulty (+15% at Torment 1 to +131% at T6) ([Diablo Wiki: Legendary Pity Timer](https://www.diablowiki.net/Legendary_Pity_Timer), [Torment](https://www.diablowiki.net/Torment)) **[snippet]**. Sinks: D3 salvages every rarity into one of four materials, with Forgotten Souls only from world-dropped legendaries, and Kanai's Cube reforges for 50 souls ([Diablo Wiki: Salvage](https://www.diablowiki.net/Salvage), [Maxroll: Kanai's Cube](https://maxroll.gg/d3/resources/kanais-cube)) **[snippet]**; the destructive alternatives — MapleStory Star Force (95% → 1% success with 2.1–19.8% destruction from 15★) and Lost Ark honing (down to 0.5% with 0.465× Artisan's Energy pity) — exist to sell safeguards ([maple starforce.ts](https://github.com/iamnbutler/maple/blob/a18c667de7e3003d02d51499636bde6b26fc1b25/src/lib/data/starforce.ts), [Lostark-helper honing-chances.ts](https://github.com/Supamiu/Lostark-helper/blob/0431f5f33202ad40258b6c550a4e47c384762c51/apps/client/src/app/pages/honing-cost-optimizer/honing-chances.ts)) **[code]**. Inventory tedium is solved at drop time: NGU's Improved Loot Filter discards by exact item and AutoMerge slots absorb duplicates; Melvor's Amulet of Looting auto-banks and the bank sells per tab; D4 shipped a native filter with item-power and Greater-Affix conditions ([NGU guide inventory.md](https://github.com/sayolove/ngu-guide/blob/aa50a4ffe38f6dbf6bc1390edd616bee7f6cf668/src/content/docs/en/mechanics/inventory.md), [Melvor Wiki: Bank](https://wiki.melvoridle.com/w/Bank), [D4Scanner](https://github.com/defessler/D4Scanner/blob/6418927743523e405092c4b658f982fa0e2791d9/docs/d4-gearing-knowledge.md)) **[doc; snippet]**.

### Active play, offline, onboarding, achievements and dailies

Cookie Clicker is the genre's high end for active bonuses: golden cookies spawn on a 5–15-minute base window (`m=5`, `m=15`, halved by Lucky day and Serendipity), stay 13 s, and grant Frenzy ×7 for 77 s or Click Frenzy ×777 for 13 s; "Lucky" pays `min(15% of bank, 15 min of CpS) + 13` ([ozh/cookieclicker main.js](https://github.com/ozh/cookieclicker/blob/master/main.js)) **[code]** — roughly 2× idle early and ~5× at high spawn rates **[computed]**. Clicker Heroes takes the opposite stance: idle multipliers (Siyalatas, Libertas) switch on only after 60 s without input, with a per-level value that starts at +25% and decays to +15% ([derivagral ancientsworker10.js](https://github.com/derivagral/clicker_hero/blob/master/static/js/ancientsworker10.js), [Clicker Heroes idle DPS guide](https://blog.clickerheroes.com/clicker-heroes-idle-dps-the-ultimate-guide/)) **[code; snippet]**. OSRS's active techniques cluster at +20–50% throughput (2-tick cooking is "30–40% faster than afk cooking") ([OSRS Wiki: Cooking](https://oldschool.runescape.wiki/w/Cooking)) **[code-dump]**, IdleOn gates its mini-games by daily plays (+4 per Gem Shop purchase) ([DigitalTQ: Daily Minigame Plays](https://www.digitaltq.com/wiki/idleon/items/misc/daily-minigame-plays-1953)) **[snippet]**, and RuneScape removed its forced random events because they "only provided hindrance and annoyance to legitimate players" ([OSRS Wiki: Random events](https://oldschool.runescape.wiki/w/Random_events)) **[snippet]**.

Offline rules fall into two families. Full simulation capped by time: Melvor replays every 50 ms tick up to `maxOfflineTicks = 20·60·60·24` (24 h), including combat with food, potion charges and death, and offers combat offline only behind a toggle ([Melvor game.js](https://github.com/ChanceToZoinks/melvor-source/blob/main/src/game.js)) **[code]**; Trimps' Time Warp runs the real loop for `maxTicks: 864000` (24 h) with a cheaper gatherer-only fallback beyond that, ignoring absences under 60 s ([Trimps main.js](https://github.com/Trimps/Trimps.github.io/blob/master/main.js)) **[code]**; Antimatter Dimensions bounds *resolution* instead — at most 1e5 ticks, each ≥ 33 ms "(this would allow offline to exploit tick microstructure)" and ≤ 1 day, with a progress modal and Speed-up/Skip buttons ([AD storage.js](https://github.com/IvarK/AntimatterDimensionsSourceCode/blob/master/src/core/storage/storage.js), [game.js](https://github.com/IvarK/AntimatterDimensionsSourceCode/blob/master/src/game.js)) **[code]**. Reduced efficiency capped by time: Cookie Clicker pays 5% of CpS for 1 h, one-tenth beyond, upgradeable to 91% for 7 d 8 h ([main.js](https://github.com/ozh/cookieclicker/blob/master/main.js)) **[code]**. Melvor's cap rose from 12 to 18 to 24 h under player pressure but never went uncapped ([MelvorIdle issue #1703](https://github.com/MelvorIdle/melvoridle.github.io/issues/1703)) **[code-hosted issue]**, and its bug tracker shows what breaks when offline uses a different path than online (Adventure-mode mining at 38% of expected, #1126; background-tick loss on Android, #4740) ([issue #1126](https://github.com/MelvorIdle/melvoridle.github.io/issues/1126), [issue #4740](https://github.com/MelvorIdle/melvoridle.github.io/issues/4740)).

Onboarding in every reachable implementation is state-driven: Kittens Game hides every tab but Bonfire and reveals each by predicate (`visible = condition`), Antimatter Dimensions highlights the next button through six states (second dimension at 100 antimatter), and Trimps' advisor window advances on what the player has done and jumps veterans to step 15 ([kittensgame game.js](https://github.com/nuclear-unicorn/kittensgame/blob/master/game.js), [AD tutorial.js](https://github.com/IvarK/AntimatterDimensionsSourceCode/blob/master/src/core/tutorial.js), [Trimps objects.js](https://github.com/Trimps/Trimps.github.io/blob/master/objects.js)) **[code]**; Melvor's tutorial completes at 83 XP ([Melvor Wiki: Beginners Guide](https://wiki.melvoridle.com/w/Beginners_Guide)) **[snippet]**. Achievements grant real power via count-based multipliers: Cookie Clicker's milk is `AchievementsOwned/25` feeding 17 kitten upgrades, AD's global power is `1.25^rows × 1.03^count`, Evolve adds 0.25% per achievement level, Trimps applies `1 + achievementBonus/100` ([cookieclicker main.js](https://github.com/ozh/cookieclicker/blob/master/main.js), [AD normal-achievement.js](https://github.com/IvarK/AntimatterDimensionsSourceCode/blob/master/src/core/achievements/normal-achievement.js), [Evolve achieve.js](https://github.com/pmotschmann/Evolve/blob/master/src/achieve.js), [Trimps main.js](https://github.com/Trimps/Trimps.github.io/blob/master/main.js)) **[code]**; only Melvor keeps completion cosmetic until 100%, when the Cape of Completion grants 5% DR ([Melvor Wiki: Cape of Completion](https://wiki.melvoridle.com/w/Cape_of_Completion)) **[snippet]**. Daily loops that work are bankable: NGU's spin banks 36 h by default and 7 days with an upgrade, Cookie Clicker's sugar lump ripens at 23 h, auto-harvests at 24 h and credits missed lumps on load ([NGU Wiki: Daily Spin](https://ngu-idle.fandom.com/wiki/Daily_Spin), [cookieclicker main.js](https://github.com/ozh/cookieclicker/blob/master/main.js)) **[snippet; code]**; streaks are a documented dark pattern that "get people to pay to avoid punishment" ([DarkPattern.games: Daily Rewards](https://www.darkpattern.games/pattern/11/daily-rewards.html)) **[snippet]**.

### Persistence, cheat resistance and UI

Every reachable browser idle stores JSON in localStorage and exports a compressed, versioned string: Cookie Clicker refuses saves "from a future version" and migrates with inline `if (version < …)` checks; Antimatter Dimensions deflates with pako, Base64-encodes with character substitutions, wraps the string in a magic prefix/suffix, applies a numeric migration chain (1 … 25) in order, keeps 3 slots × 8 timed backups (1 min / 5 min / 20 min / 1 h online; 10 min / 1 h / 5 h offline), hashes cloud saves with SHA-512/256 and resolves conflicts by comparing progress *and* real time played, always prompting when the two signals disagree ([cookieclicker main.js](https://github.com/ozh/cookieclicker/blob/master/main.js), [AD serializer.js](https://github.com/IvarK/AntimatterDimensionsSourceCode/blob/master/src/core/storage/serializer.js), [migrations.js](https://github.com/IvarK/AntimatterDimensionsSourceCode/blob/master/src/core/storage/migrations.js), [cloud-saving.js](https://github.com/IvarK/AntimatterDimensionsSourceCode/blob/master/src/core/storage/cloud-saving.js)) **[code]**; Trimps, Kittens and Evolve use LZString ([Trimps main.js](https://github.com/Trimps/Trimps.github.io/blob/master/main.js), [kittensgame game.js](https://github.com/nuclear-unicorn/kittensgame/blob/master/game.js), [Evolve main.js](https://github.com/pmotschmann/Evolve/blob/master/src/main.js)) **[code]**. Melvor's tracker documents the failure modes: last-write-wins cloud sync cost a player "nearly 3 months of progress" (#4094), and reload-to-reroll chest exploits were closed as `notabug` with the reporter's suggestion that chests be pre-rolled at drop time (#2328) ([issue #4094](https://github.com/MelvorIdle/melvoridle.github.io/issues/4094), [issue #2328](https://github.com/MelvorIdle/melvoridle.github.io/issues/2328)) **[code-hosted issues]**. Client-side hashing of scores "probably does nothing" because the salt ships in the build; anything of value must be server-computed ([Marvin Advergames devlog](https://marvinadvergames.itch.io/cloud-leaderboard-kit-for-construct-3/devlog/1642569/your-leaderboards-anti-cheat-probably-does-nothing-heres-what-actually-works)) **[snippet]**, which is why Firestone rewrote "99% of the game" server-side after cheat-engine abuse while leaving the main battle client-side ([Steam: Firestone](https://steamcommunity.com/app/1013320/discussions/0/4363502774085386591)) **[snippet]**. Number formatting is consistent: full digits with separators to 999,999 then K/M/B (Cookie Clicker engages suffixes at 1,000,000; Kittens at 9,000), scientific as an option ([cookieclicker main.js](https://github.com/ozh/cookieclicker/blob/master/main.js), [kittensgame game.js](https://github.com/nuclear-unicorn/kittensgame/blob/master/game.js), [AD notations.js](https://github.com/IvarK/AntimatterDimensionsSourceCode/blob/master/src/core/notations.js)) **[code]**; Melvor players complain about repeated, non-dismissable welcome-back modals (#4620, #2321) and a cluttered sidebar ([issue #4620](https://github.com/MelvorIdle/melvoridle.github.io/issues/4620), [Steam: Why is the UI so boring?](https://steamcommunity.com/app/1267910/discussions/0/3944650879129936794/)) **[issue; snippet]**.

### Social and endgame: asynchronous or nothing

### Economy: give every resource a consumer and every tier a price

Adopt OSRS's escalating coal schedule for smelting — copper 0, iron 1 (already), silver 0, gold 0, **mithril 4, adamant 6, runite 8** **[code-dump]** — and OSRS's bars-per-slot rule instead of a flat 5: Weapon 2, Shield 3, Head 2, Body 5, Legs 3, Boots 1, Gloves 1 (17 bars per set), with smithing XP = bars × per-tier XP (12.5 / 25 / 37.5 / 50 / 62.5 / 75 per bar for copper → runite) **[code-dump]**. Give smithing real level gates using "tier base + slot offset": copper 1, iron 15, mithril 50, adamant 70, runite 85; Weapon +0, Boots +1, Gloves +2, Head +3, Shield +8, Legs +16, Body +18, capped at 99 — this alone yields a new unlock at nearly every level and finally gives the dead smithing/crafting levels a job **[code-dump; mapping is inference]**. Remove silver and gold bars from the armour dropdown and make them jewellery-only metals (OSRS/Melvor), with jewellery power = bar + gem and a gem-cutting step that grants crafting XP on OSRS's ladder (opal 15 … diamond 107.5) **[code-dump]**. Make logs the cooking fuel (one log per cook, log tier ≥ food tier), which mirrors OSRS's "interlaced" woodcutting → firemaking → cooking chain and gives five dead woods a consumer immediately **[code-dump; rule is inference]**; add Firemaking (log → XP plus a timed bonfire XP buff, Melvor's `bonfireBonusXP`) in Phase 4 **[code]**. Keep alchemy's existing pattern of a herb plus a secondary from another skill and extend it to mining and woodcutting potions (Melvor's rule: the secondary comes from the skill the potion buffs) **[snippet]**.

Split gold into two currencies, which is what the prestige modal already claims: **gold** (skilling, persistent) and **combat gold** (run-scoped, wiped on prestige as Clicker Heroes wipes gold on ascension). Combat gold per kill is `ceil(HP(s)/15 × min(3, 1.025^max(0, s−75)))` — 3 at stage 10, 629 at stage 50, 20,680 at stage 75, 1.26 M at stage 100 — with bosses paying ×5 through their HP and a 1% treasure enemy paying ×10 **[code; values computed]**. Reprice selling so that value scales with tier (≈ ×3–5 per material tier, sell price 60% of value) and every crafted item's value exceeds the sum of its inputs' values, OSRS's rule **[code-dump]**; delete the flat 6/18 price table. Sinks in priority order: the tool chains above; loot-bag and bank slots on Melvor's `floor(2654570 × 50·L / 142015^(163/(120+L)))` curve capped at 5,000,000 **[code]**; auto-eat tiers I–III (Melvor's Tier I is ~1,000,000 GP) **[snippet]**; an in-dungeon gear-swap unlock; salvage-material conversion. Reprice or remove the Coal Wagon (its 100 coal must cost more than 100 × coal's sell price) and delete the Healing Potion.

### Combat and prestige: exponential tokens, rating-based mitigation, gold-funded run growth

Keep the enemy curve — `HP = 10 × 1.15^(s−1)`, `ATK = 1.1^(s−1)`, boss every 10 stages at ×5 HP / ×2 ATK — because 1.15 per stage is Clicker Heroes' mid-game slope (×4.05 per 10 stages vs CH's ×3.87) **[code]**, and add CH/TT2's **30-second boss timer** with "fail → drop back and farm" plus a progress/farm toggle so death never loops into the same wall **[code; snippet]**. Replace the flat subtraction `dmg = enemyAtk − def` with a rating: `DR = min(0.90, DEF / (DEF × 10/9 + C(s)))` with `C(s) = k × ATK(s)`, k = 1 as a starting value, so a boss's ×2 ATK becomes a graceful ~1.4× damage step instead of a cliff from immunity to 23 per hit (D4's armour form, Melvor's 95% cap) **[doc; k is inference]**. Stop refilling HP on every spawn; use Melvor's model — regen `maxHP/100` every 10 s, auto-eat when `HP ≤ threshold` (tiers 20/30/40%) refilling to 40/60/80% at 60/80/100% efficiency, idle-safe iff `maxHP × threshold ≥ maxHit × (1 − DR)` **[code; tier values snippet]** — so food becomes a real consumable and offline combat can end on death. Cap the secondary stats: crit chance summed across slots and capped at 50%, attack-speed bonus summed and capped at +100%, dodge converted to a rating `R/(R + K)` capped at 75%, lifesteal ≤ 1.2% per affix on at most two slots **[code (PoB); TT2 crit cap code]**.

The prestige engine is the single most important change. Set **`tokens(S) = floor(2^((S − 10)/5))`** for S > 10 and give **+10% ATK, DEF and max HP per token held** (`1 + 0.1 × T`, Clicker Heroes' `heroSouls × 10` percent) **[code; formula is inference sized to the note's `4^(S/10)` rule]**. Because 2^(1/5) = 1.149 tracks the 1.15 HP base, the held multiplier grows at the enemy's rate: 4 tokens at stage 20, 256 at 50, 262,144 at 100 and 2.75 × 10^11 at 200, against HP ratios of 14, 942, 1.02 × 10^6 and 1.2 × 10^12. In a fixed-gear kill-time model starting from the audit's common-iron wall at stage 40, each prestige then moves the wall by a constant **+13–14 stages** (40 → 54 → 68 → 81 → 94 → 107 …), whereas a weaker base of 1.1 per stage converges (40 → 47 → 51 → 52 → 54) exactly as the shipped `stage^1.5` does ([redesign-pacing.mjs](file:///tmp/claude-0/-home-user-idle2/822a3f17-4006-5034-be72-45cc3ca07351/scratchpad/redesign-pacing.mjs)) **[simulated]**. Keep the token shop's doubling costs (`base × 2^level`) but restrict it to non-combat multipliers — gathering speed +10%/level (cap 20), offline-cap hours, auto-progress, Book of Shadows +20%/level at `floor(5 × 2.5^n)` (cap 10) — so that spending tokens trades combat power for skilling speed, CH's ancients tension; with exponential income, a doubling cost simply means "each level costs five more stages", which is the right price. Keep the 10%-of-best start stage as quality of life. Cut skill points and fold Knight/Warlord/Rogue into achievements. For within-run growth, add a run-scoped "camp" shop bought with combat gold — `cost = 10 × 1.07^owned`, +5% ATK/DEF per level, ×2 milestones at 25/50/100 levels, reset on prestige — which reproduces the production-vs-cost seesaw (CH heroes at ×1.07; Pecorella's milestone spikes) and makes each run stall gradually **[code; mirror]**. Optional: once combat levels exist (Hitpoints XP at 0.133 per damage), compute base damage with Melvor's `floor(10 × (1.3 + L/10 + B/80 + L·B/640))` so levels and gear multiply **[code]**. Bound the click overlay: a click is one 0.5× attack, combo capped at 50 with a 30 s cooldown after a full combo, so an active player's expected throughput stays ≤ ~2× idle (CH 3.5%-of-DPS clicks, TT2 20 taps/s) **[snippet; code; cap values inference]**.

### Items: quality plus affixes, tier-gated drops, deterministic sinks

Rewrite the generator. Base power stays `tierPower × slotMultiplier × variance(0.9–1.1)` with the existing `EQUIP_MULTIPLIERS`, but rarity becomes **quality + affix count**: common +0% / 0 affixes, uncommon +10% / 1, rare +20% / 2, epic +35% / 3, legendary +50% / 4, with at most two prefixes and two suffixes and the +50% ceiling mirroring D4's 1.5× Greater Affix; a tier-N common must beat a tier-(N−1) legendary, which holds as long as the per-tier power ratio (currently ×2.5) exceeds 1.5 **[doc; PoE code; values inference]**. Affixes come from a pool with per-slot spawn weights and item-level-gated tiers whose top tiers are lower-weighted (PoE's 1,000 → 25) **[code]**; the pool is offensive (crit, crit damage, attack speed), defensive (dodge rating, DR%, HP), and economic (gold find, XP, drop rate — additive, ≤ 26% per affix, jewellery/helm/gloves/boots only) **[code]**. Use the WoW palette (white/green/blue/purple/orange) **[Wikipedia snippet]**. Crafted items roll common 70% / uncommon 25% / rare 5% and never epic or legendary: crafting is the deterministic base (Melvor's ladder, PoE's "buy the base"), and higher quality comes from combat **[inference from code data]**. Drops use a two-stage roll — `P(drop)` by enemy class (trash 5–10%, elite 25–50%, boss 100%), then base type from the enemy's tier ±1, then rarity weights that shift toward rare/epic with enemy tier via a D2-style `(mlvl − qlvl)` term and never legendary below the tier's cap **[snippet; inference]**. Trash tables should be ~99% materials and ≤ 1% gear (Melvor's Shaman pattern), zone-capstone uniques 0.1–0.5% per boss or dungeon clear, and fragments (10 → item) at 3–12% per kill as visible pity **[code]**; a D3-style hidden pity timer of ~2 hours is optional **[snippet]**. Sinks: salvage every rarity into one of four materials (D3), with the top material dropping only from combat so combat is mandatory for epic/legendary quality; deterministic upgrade ranks 0–25 at +1% per rank paid in those materials with cost `floor(3.75 × rank + 10)` units (D4 masterworking); one-affix reroll with escalating, capped cost (D3 Mystic / D4 enchant); set bonuses by material-tier count (e.g. 4 runite pieces: +5% DR, Melvor's trimmed-armour DR values); no destruction, no sockets **[snippet; doc; code]**. Cap the rolled-item bag at 20–40 with overflow auto-salvaged rather than discarded, stack all materials, ship an item lock and a drop-time filter (rarity, tier below equipped, affix present) plus a one-click "upgrade if better, else salvage" rule **[doc; inference]**. Make the "(Lv N)" label real: item level = tier base, wearable when a new Hitpoints-style combat level (0.133 XP per damage) meets it, or cut the label.

### Active play and offline: cap uptime, replay everything, cap at 24 hours

Convert the minigames from always-available to opportunity-based: a prompt appears every 3–8 minutes (Cookie Clicker's 5–15-minute base, with `Math.random() < ((t − min)/(max − min))^5` clustering spawns late) and stays ~13 s; success grants +50–100% skill speed for 60–120 s; failure or expiry costs nothing, and a streak only raises the bonus toward the cap **[code; values inference]**. Add a CH-style **focus bonus of +15% after 60 s without input** that also applies offline, so idle play is never dominated **[code; snippet]**. The expected ceiling for a fully active player is then ~1.5–2× idle — the OSRS +20–50% precedent, not Cookie Clicker's ×777.

Offline must run the same tick code as online for whatever action is active — gathering, workshop and combat with food, potions, regen and death — capped at **24 hours** (Melvor's `20·60·60·24` ticks, Trimps' 864,000), batching whole actions rather than 50 ms frames and honouring AD's bounds (no tick shorter than 33 ms, no more than 1e5 simulated ticks), ignoring absences under 60 s, and stopping on death or exhausted inputs **[code]**. When a server session exists, derive the elapsed time from the server's `receivedAt` of the last save, never from `Date.now()`. Show one queued, dismissible summary with per-hour rates (food per hour, XP per hour) and a "speed up / skip" control for long replays **[code]**.

### Onboarding, achievements and dailies: predicates, one multiplier, one bankable cache

Delete the forced-unlock override and the deleted staged tutorial alike; gate each tab by a state predicate evaluated every tick — Smithing when 5 ore are held, Combat at mining 3 or the first bar, Crafting on the first gem, Alchemy at hunting 5, Prestige at `maxStage ≥ 10`, Dungeons at `maxStage ≥ 20`, Clan after the first prestige — and guide with a re-openable, flashing advisor panel and a highlighted next action (Trimps, AD), never a modal **[code; thresholds inference]**. ### Persistence, cheat resistance and UI: version everything, trust nothing from the clock

Wrap the save as `{ version, savedAt, state }` with derived fields (`stats`, `combat.enemy`, `inventoryOrder`, `activePlay.challenge`) stripped, an AD-style ordered migration map applied while `save.version < key`, refusal of newer versions with a message, an export string compressed with LZString or pako + Base64 inside a magic prefix/suffix, rolling backups on AD's schedule (1 min / 5 min / 20 min / 1 h online; 10 min / 1 h / 5 h offline), a per-user storage key, and autosave every 10 s plus on `visibilitychange`/`pagehide` and immediately before any irreversible RNG (chest opening, prestige) **[code]**. Phases 0 and 1 are strictly ordered: the harness-verified bugs must be fixed on the existing code so that the simulator in Phase 1 can be validated against real behaviour (the audit's analytic resolver was cross-checked against a tick-by-tick simulation and against the real loop; keep that discipline). Phase 1 should be built as pure functions over data tables — `xpForLevel(L)`, `intervalFor(node, modifiers)`, `enemyAt(stage)`, `tokensFor(stage)`, `rollItem(tier, slot, source)` — so the same module drives the game loop, the offline replay and the simulator; this is the property that made Melvor's offline "identical to online" and whose absence produced its #1126 and #4740 bugs **[code-hosted issues]**. Phase 2 comes before loot because offline, onboarding and saves are what a returning player touches first, and because a versioned save format must exist before Phase 3 adds item instances with affixes. Phase 3 before Phase 4 because dungeons and drops give combat its missing rewards and materials, which Farming and Agility then consume. The social layer is last on purpose: the strongest single-developer comparables thrived without it, the failures (Firestone's rewrite, IdleOn's party bugs, RuneScape's citadels) all came from social features whose rewards or synchrony outran the backend, and the async clan boss should reuse the titan/dungeon code path so that Phase 5 is mostly Postgres logic. Explicitly deferred: Ranged/Magic combat styles with Fletching/Runecrafting (L), Township or Summoning-scale systems, real-time chat, synchronous party content, gacha pets, and any purchasable power.

## Conclusion

The audit reframes Fantasy Idle's problem: it is not an unfinished game with rough numbers but a game whose four load-bearing curves — XP, rarity, enemy scaling and prestige — are each individually shaped so that progress stops, and whose one bridging system (equipment) has never executed. That makes the fix unusually clean. Every replacement curve recommended here is lifted from a source that could be read as code rather than prose — RuneLite's XP loop, Melvor's interval and mastery functions, Clicker Heroes' gold and soul formulas, Antimatter Dimensions' save pipeline, Path of Building's affix tables — and the one genuinely new formula, `tokens = floor(2^((S−10)/5))` with a held +10% per token, is derived from the requirement that the prestige multiplier grow at the enemy's own rate; the pacing script shows it turns a converging loop (40 → 47 → 51 → 52) into a constant-gain one (40 → 54 → 68 → 81). The developer should treat the parameter values as sim inputs and the formula *shapes* as the design, which is how the comparables themselves were balanced.

The second implication is about order. Because the game is client-only and the comparables that stayed client-only (Melvor, Idle Champions) are also the ones that stayed sustainable for one developer, everything with a server dependency belongs at the end, behind a monetization decision, and everything that makes a single player's first three hours coherent — a working generator, a curve that unlocks mithril in 22 minutes instead of 46 days, an offline replay that includes combat, a save that survives logout — belongs at the start. The numbers that most need spot-checking before adoption are the **[snippet]** ones: Melvor's auto-eat tiers and tool percentages, the wiki-reported guild caps, and the Vercel/Neon plan limits; every other figure in this report traces to executed code, a simulation of the game's own formulas, or a source file the researchers read.
